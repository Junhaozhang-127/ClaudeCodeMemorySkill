## 第二阶段：摘要与关键词增强（当前开发中 🔧）

**目标**：提升记忆摘要质量和检索精度，让记忆库真正可用。

| 任务 | 优先级 | 状态 | 说明 |
|------|--------|------|------|
| 可插拔摘要器架构 | 高 | ✅ 已完成 | `BaseSummarizer` ABC + `SummaryResult` dataclass，支持依赖注入 |
| 规则版摘要器 | 高 | ✅ 已完成 | `RuleBasedSummarizer`：句子分割、摘要生成、决策/待办抽取 |
| 关键决策自动抽取 | 高 | ✅ 已完成 | 基于触发词表匹配，最多 5 条，无匹配返回空列表 |
| 待办事项自动抽取 | 高 | ✅ 已完成 | 基于触发词表 + 列表项检测，最多 8 条 |
| 中文关键词增强 | 中 | ✅ 已完成 | jieba 分词优先 + 正则回退，含中英文停用词过滤 |
| 停用词过滤 | 中 | ✅ 已完成 | 中英文共计 ~100 词 |
| 检索评分优化 | 高 | ✅ 已完成 | 多字段加权（主题>关键词>决策/待办>摘要）+ 时间衰减 |
| format_context 优化 | 中 | ✅ 已完成 | 优先输出摘要→决策→待办→内容 |
| index.json 元数据扩展 | 中 | ✅ 已完成 | 新增 decisions/todos 字段，向后兼容 |
| 技术实体识别 | 中 | ⏳ 未来 | 识别框架名、库名、API 名、文件名等技术实体 |
| LLM 摘要生成 | 高 | ⏳ 第三阶段 | 接入 Claude API 或本地模型（架构已预留接口） |
| 摘要长度自适应 | 低 | ⏳ 未来 | 根据对话长度动态调整摘要长度 |

**技术选型（已实施）**：
- 可插拔架构：`BaseSummarizer` 抽象基类 + 依赖注入
- 中文分词：jieba（可选依赖，自动回退到正则规则法）
- 结构化抽取：触发词表 + 句子分割规则法
- 检索评分：多字段加权（主题 15/token 5，关键词 4，决策/待办 3，摘要 2）+ 时间衰减 +2

**技术选型（待实施）**：
- LLM 摘要：通过 `subprocess` 调用 Claude Code CLI 或直接使用 Anthropic SDK
- 实现 `BaseSummarizer` 接口即可无缝替换

**目标**：将 Memory Skill 升级为接近生产级的记忆系统。

### 检索增强

| 任务 | 说明 |
|------|------|
| 向量检索 | 使用 sentence-transformers 或 OpenAI Embeddings 做语义相似度搜索 |
| 混合检索 | 关键词匹配 + 向量相似度的加权混合排序 |
| 时间衰减 | 较旧的记忆自动降权，近期记忆优先 |

## 技术原则

贯穿四个阶段的工程原则：

1. **渐进增强**：每个阶段独立可用，不因为后续阶段而阻塞当前交付
2. **向后兼容**：`index.json` 格式、Markdown 文件格式、CLI 接口尽量不破坏
3. **可降级**：LLM 不可用时回退到规则法，向量库不可用时回退到关键词匹配
4. **零强制依赖**：核心功能始终可用标准库运行，增强功能作为可选依赖
5. **文件可读**：记忆文件和索引始终保持人工可编辑的纯文本格式
