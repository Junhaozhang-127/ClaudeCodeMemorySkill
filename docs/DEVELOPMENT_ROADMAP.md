# 开发路线图

## 第二阶段：摘要与关键词增强

**目标**：提升记忆摘要质量和检索精度，让记忆库真正可用。

| 任务 | 优先级 | 说明 |
|------|--------|------|
| 可插拔摘要器架构 | 高 | 将 `simple_summary()` 改为可配置的摘要策略接口，支持截断、LLM、模板等多种实现 |
| LLM 摘要生成 | 高 | 接入 Claude API 或本地模型，从对话中提取结构化摘要 |
| 关键决策自动抽取 | 高 | 从对话中识别"我们决定..."、"最终方案是..."等决策语句 |
| 待办事项自动抽取 | 高 | 从对话中识别"TODO"、"需要后续..."、"下一步"等 |
| 中文关键词增强 | 中 | 引入 jieba 分词，替换纯正则关键词抽取 |
| 停用词过滤 | 中 | 过滤"的"、"是"、"在"等无意义中文词 |
| 技术实体识别 | 中 | 识别框架名、库名、API 名、文件名等技术实体作为关键词 |
| 摘要长度自适应 | 低 | 根据对话长度动态调整摘要长度 |

**技术选型建议**：
- 中文分词：jieba（纯 Python，轻量）
- LLM 摘要：通过 `subprocess` 调用 Claude Code CLI 或直接使用 Anthropic SDK
- 抽取策略：先用规则法做快速抽取，LLM 作为高质量备选

## 第三阶段：Claude Code 生态接入

**目标**：让 Memory Skill 成为 Claude Code 原生体验的一部分。

| 任务 | 优先级 | 说明 |
|------|--------|------|
| 正式 Hook 配置 | 高 | 根据 Claude Code 实际 Hook 规范，生成可直接使用的 `settings.json` 配置 |
| Skill 注册 | 高 | 将项目注册为 Claude Code 可识别的 Skill，支持 `/memory` slash command |
| 交互式检索命令 | 中 | 实现 `/memory-search` 或 `/memory-list` 等对话内命令 |
| Plugin 打包 | 中 | 按 Claude Code Plugin 规范打包，支持一键安装和配置 |
| 记忆浏览命令 | 低 | `/memory-recent` 查看最近记忆，`/memory-topics` 列出所有主题 |
| 自动 Hook 安装脚本 | 低 | 一键配置脚本，自动添加 Hook 到 settings.json |

## 第四阶段：高级能力（可选）

**目标**：将 Memory Skill 升级为接近生产级的记忆系统。

### 检索增强

| 任务 | 说明 |
|------|------|
| 向量检索 | 使用 sentence-transformers 或 OpenAI Embeddings 做语义相似度搜索 |
| 混合检索 | 关键词匹配 + 向量相似度的加权混合排序 |
| 时间衰减 | 较旧的记忆自动降权，近期记忆优先 |
| 检索缓存 | 缓存最近检索结果，减少重复计算 |

### 记忆管理

| 任务 | 说明 |
|------|------|
| 记忆合并 | 同主题多次写入自动合并为一条完整记忆 |
| 记忆去重 | 检测内容高度相似的多条记忆并提示合并 |
| 记忆归档 | 超过 N 天未访问的记忆自动归档到 `memory/archive/` |
| 手动标记 | 支持用户标记重要记忆（star/pin） |

### 工程增强

| 任务 | 说明 |
|------|------|
| 项目级隔离 | 按 Git 仓库或项目名自动隔离记忆存储目录 |
| 并发安全 | 文件锁（`fcntl` / `msvcrt`）保护 `index.json` 写入 |
| 日志系统 | 记录写入、检索、错误日志，便于调试和监控 |
| 配置系统 | 支持 `config.yaml` 或 `config.json` 统一管理参数 |
| CLI 增强 | 丰富命令行参数，支持 `--project`、`--since`、`--format` 等 |

### 可选 UI

| 任务 | 说明 |
|------|------|
| Web 浏览界面 | 简单的 Flask/FastAPI 页面，浏览和搜索记忆 |
| VS Code 扩展 | 在 VS Code 侧边栏中查看和管理记忆 |

## 技术原则

贯穿四个阶段的工程原则：

1. **渐进增强**：每个阶段独立可用，不因为后续阶段而阻塞当前交付
2. **向后兼容**：`index.json` 格式、Markdown 文件格式、CLI 接口尽量不破坏
3. **可降级**：LLM 不可用时回退到规则法，向量库不可用时回退到关键词匹配
4. **零强制依赖**：核心功能始终可用标准库运行，增强功能作为可选依赖
5. **文件可读**：记忆文件和索引始终保持人工可编辑的纯文本格式
